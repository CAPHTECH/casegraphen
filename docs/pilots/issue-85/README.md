# Issue 85 graph-runtime durability evidence

This directory retains bounded local evidence for graph/runtime durability.
It supplements issue #76; it does not replace provider-specific, broker-signed
host/session attestations and cannot promote experimental v0.

The evidence has four independent lanes:

- `remote`: a real loopback TCP server in a separate process. The client
  observes disconnect after durable receipt, duplicate delivery, timeout,
  process restart, reconnect, and idempotent journal resume.
- `binary`: 65,536 deliberately non-UTF-8 bytes are presented to
  `observe_runtime_artifact` and joined by the canonical runtime reconciler
  across a source-output/target-input edge. The retained raw bytes, typed
  reports, expectation, and edge proofs are content-addressed evidence.
- `scale`: 512 nodes, 511 data edges, 128 real retry predecessors and 640 typed
  reports are processed by `derive_runtime_graph_expectation` and
  `reconcile_runtime_reports`, with explicit latency and child-RSS thresholds.
- `allocator`: the real `UnreviewedResourceJournal` implementation appends 512
  hash-chained events and exercises restart/replay, concurrent exclusive
  reservation, release, supersede, pre-publication crash residue, and
  post-publication corruption refusal. It is intentionally mechanics-only and
  grants no deployment authority. Full replay remains O(events); the report
  records the lack of checkpoint/compaction as an explicit production blocker.

The `reviewed_resource` lane independently runs the operational host's exact
topology review, reviewed compile, reviewed allocator reservation, and
resource-bearing runtime reconciliation. Its bundle hash is required to equal
the hash retained by the canonical scale/binary report.

Every lane has a fixed bound. A failed or timed-out lane makes the harness exit
non-zero after writing its failed report. All runtime results remain
`accepted: false`, stop at operator review, and can produce only unreviewed
audit/redesign proposals.

Regenerate from the repository root:

```sh
CASEGRAPHEN_REVIEWED_RESOURCE_PILOT_REPORT=/tmp/reviewed-resource.json \
  cargo test --test resource_host_e2e \
  operational_host_reserves_then_reconciles_a_resource_bearing_run_to_review \
  -- --exact
cargo run --example runtime_reconciliation_durability_pilot -- \
  /tmp/canonical-runtime \
  "$(python3 -c 'import json; print(json.load(open("/tmp/reviewed-resource.json"))["reviewed_deployment_hash"])')"
cargo run --example resource_allocator_durability_pilot -- \
  /tmp/allocator-durability-report.json
python3 scripts/runtime-durability-pilots.py \
  --repo . \
  --allocator-report /tmp/allocator-durability-report.json \
  --canonical-runtime-dir /tmp/canonical-runtime \
  --reviewed-resource-report /tmp/reviewed-resource.json \
  --canonical-peak-memory-bytes <measured-child-peak-rss-bytes> \
  --output /tmp/casegraphen-issue-85
```

Run the final command in an environment that permits loopback sockets. The
checked-in `retained-evidence.manifest.json` hashes the raw remote journal,
binary artifact, topology, expectation, reports, completeness result,
allocator report, reviewed-resource report, and aggregate reports.

The checked-in report binds the observed source revision, dirty-state flag,
harness hash, experimental contract hashes, and runtime versions. Because a
report committed inside the source tree cannot contain its own future commit
hash without a hash cycle, `source_revision` names the executed parent commit
and the retention manifest binds the exact generated bytes. Release automation
must additionally bind the immutable workflow artifact to its commit; that
provider-host evidence remains issue #76's responsibility.
