# Issue 85 graph-runtime durability evidence

This directory retains the **last checked-in baseline** for bounded
graph/runtime durability. It supplements issue #76; it does not replace
provider-specific host/session authority and cannot promote experimental v0.
No later generated runtime evidence may be added here. Future runs are retained
as content-addressed GitHub Release assets by
`runtime-durability-evidence.yml`; only their small
`runtime_durability.retention_record.v1` pointer is reviewed in Git.

The evidence has four independent lanes:

- `remote`: a real loopback TCP server in a separate process. The client
  observes disconnect after durable receipt, duplicate delivery, timeout,
  process restart, reconnect, and idempotent journal resume.
- `binary`: 65,536 deliberately non-UTF-8 bytes are presented to
  `observe_runtime_artifact` and joined by the canonical runtime reconciler
  across a source-output/target-input edge. The retained raw bytes, typed
  reports, expectation, and edge proofs are content-addressed evidence.
- `scale`: 512 nodes, 511 data edges, 128 real retry predecessors and 640 typed
  reports are processed by `derive_runtime_graph_expectation` and
  `reconcile_runtime_reports`, with explicit latency and child-RSS thresholds.
- `allocator`: the real `UnreviewedResourceJournal` implementation appends 512
  hash-chained events and exercises restart/replay, concurrent exclusive
  reservation, release, supersede, pre-publication crash residue, and
  post-publication corruption refusal. It is intentionally mechanics-only and
  grants no deployment authority. Full replay remains O(events); the report
  records the lack of checkpoint/compaction as an explicit production blocker.

The `reviewed_resource` lane independently runs the operational host's exact
topology review, reviewed compile, reviewed allocator reservation, and
resource-bearing runtime reconciliation. Its bundle hash is required to equal
the hash retained by the canonical scale/binary report.

Every lane has a fixed bound. A failed or timed-out lane makes the harness exit
non-zero after writing its failed report. All runtime results remain
`accepted: false`, stop at operator review, and can produce only unreviewed
audit/redesign proposals.

Regenerate from the repository root:

```sh
CASEGRAPHEN_REVIEWED_RESOURCE_PILOT_REPORT=/tmp/reviewed-resource.json \
  cargo test --test resource_host_e2e \
  operational_host_reserves_then_reconciles_a_resource_bearing_run_to_review \
  -- --exact
cargo run --example runtime_reconciliation_durability_pilot -- \
  /tmp/canonical-runtime \
  "$(python3 -c 'import json; print(json.load(open("/tmp/reviewed-resource.json"))["reviewed_deployment_hash"])')"
cargo run --example resource_allocator_durability_pilot -- \
  /tmp/allocator-durability-report.json
python3 scripts/runtime-durability-pilots.py \
  --repo . \
  --allocator-report /tmp/allocator-durability-report.json \
  --canonical-runtime-dir /tmp/canonical-runtime \
  --reviewed-resource-report /tmp/reviewed-resource.json \
  --canonical-peak-memory-bytes <measured-child-peak-rss-bytes> \
  --output /tmp/casegraphen-issue-85
```

Run the final command in an environment that permits loopback sockets. For this
final legacy baseline, the checked-in `retained-evidence.manifest.json` hashes
the raw remote journal, binary artifact, topology, expectation, reports,
completeness result, allocator report, reviewed-resource report, and aggregate
reports. The small `release-evidence.json` binds that manifest, evaluated
commit, topology, reviewed deployment, count, and byte budget, and explicitly
prevents treating the baseline as a published Release.

The checked-in report binds the observed source revision, dirty-state flag,
harness hash, experimental contract hashes, and runtime versions. Because a
report committed inside the source tree cannot contain its own future commit
hash without a hash cycle, `source_revision` names the executed parent commit
and the retention manifest binds the exact generated bytes.

## Future retained evidence

The Release package owns these generated roles: aggregate and promotion
reports, topology, binary artifact, canonical runtime report, expectation,
node reports, completeness result, allocator report, reviewed-resource report,
and remote journal. Its internal manifest additionally retains thresholds,
tool versions, commit SHA, workflow run/attempt, topology and reviewed
deployment hashes, and experimental contract hashes.

The package is built by the same deterministic tar/gzip implementation used by
fresh-agent evidence. Its SHA-256 determines both tag and asset name. The
publisher uses create-new, idempotent, no-clobber semantics, re-downloads the
asset, and verifies its SHA before producing a `retained_release` record.
GitHub Release administrators can still delete an asset, so this is durable,
content-addressed evidence rather than WORM storage.

The first successfully retained package is bound by
[`../issue-89/retained-release-record.json`](../issue-89/retained-release-record.json).
Workflow run `30958980480` and an independent second download both completed
strict offline verification. `release-evidence.json` binds that exact small
record while continuing to identify this directory as the final bulk baseline.

After downloading the asset and its checked-in retention record, verify the
chain without trusting the record's claims alone:

```sh
python3 scripts/runtime-durability-evidence.py verify-offline \
  --manifest /path/to/retained-release-record.json \
  --asset /path/to/sha256-<package-hash>.tar.gz
```

The command verifies the external asset hash/length, safe archive shape,
deterministic re-packaging, internal/source inventories, every evidence byte,
workflow and commit provenance, topology/deployment hashes, pass/fail boundary,
contract hashes, and tool/threshold observations. The current
`release-evidence.json` is deliberately a legacy pointer and therefore cannot
be used with this command; replace it only with the exact `retained_release`
record emitted after a successful workflow publication.

Pull-request CI uses the small synthetic fixture under
`tests/fixtures/runtime-durability/` and does not download historical Releases.
The last baseline is capped at 2,200,000 generated bytes, 1,000,000 bytes per
file, and eleven generated files. Future Release packages are capped at 64 MiB
compressed, 256 MiB expanded, and 64 archive members. The conformance gate
rejects added checked-in evidence and monitors these budgets. Provider-host
authority remains Issue #76's responsibility.
